## 1. Candidates (researched 2026-10-21)

### 1.1 Local store — `@capacitor-community/sqlite` (ADR-1)

- 🔎 Latest release: **8.1.1**, published **2026-08-06** (npm registry API: https://registry.npmjs.org/@capacitor-community/sqlite — `dist-tags.latest = 8.1.1`, `time["8.1.1"] = 2026-08-06T12:39:11Z`; accessed 2026-10-21). The 8.x series targets Capacitor 8: peerDependency `@capacitor/core: ">=8.0.0"` (same source, accessed 2026-10-21).
- 🔎 Repo: https://github.com/capacitor-community/sqlite (README, accessed 2026-10-21).
- 🔎 SQLCipher caveat: the plugin's own README states the native side uses the SQLCipher library **even for unencrypted databases**, which falls under U.S. encryption-export regulations and may require a year-end self-classification report for app distribution (README §Installation note, linked to https://discuss.zetetic.net/t/export-requirements-for-applications-using-sqlcipher/47; accessed 2026-10-21). The plugin exposes optional AES-256 encryption APIs (`setEncryptionSecret`, `androidIsEncryption` config flag) — relevant to §15 Q6 (at-rest encryption option).
- ▶ This compatibility claim is DOCUMENTATION-based (npm metadata + README peer-deps), NOT verified by execution. Compile/run must pass before ADR-1 is committed (§3 protocol).

### 1.2 Secure storage — `@aparajita/capacitor-secure-storage` (ADR-6, primary candidate)

- 🔎 Latest release: **8.0.1**, published **2026-09-23** (npm registry API: https://registry.npmjs.org/@aparajita/capacitor-secure-storage — `time["8.0.1"] = 2026-09-23T03:52:59Z`; accessed 2026-10-21). Note: release is ~4 weeks before today's access date, not "6 days" as first estimated — actual registry date recorded here governs.
- 🔎 README (https://github.com/aparajita/capacitor-secure-storage, accessed 2026-10-21): explicitly states "This plugin for **Capacitor 8**"; Android secret storage = **AES in GCM mode, key generated by Android KeyStore**, persisted in SharedPreferences; data is deleted with the app. Matches ADR-6 requirement exactly.
- 🔎 Plugin depends on `@capacitor/*
^8.0.2` (npm registry, accessed 2026-10-21).

### 1.3 Secure storage — alternative: `@capawesome-team/capacitor-secure-preferences`

- 🔎 Exists but is **NOT on public npm** — it is a **Capawesome Insiders (paid/licensed) plugin**, installed from a private registry (`npm.registry.capawesome.io` with a Polar license key). Source: https://capawesome.io/docs/sdks/capacitor/secure-preferences/ (accessed 2026-10-21). Public registry check returned "Not Found": https://registry.npmjs.org/@capawesome-team%2Fcapacitor-secure-preferences (accessed 2026-10-21).
- 🔎 Compatibility: plugin version 0.4.x ↔ Capacitor ≥8, "Active support"; 0.2.x/0.3.x deprecated. Encrypts at rest using the Android Keystore / iOS Keychain. Sources: capawesome.io docs page + https://capawesome.io/blog/how-to-securely-store-credentials-with-capacitor/ (accessed 2026-10-21).
- 🔎 **Brief comparison:** aparajita is free/open, MIT-ish ecosystem, Capacitor 8-stated, AES/GCM+Keystore — sufficient for FR-14/Q7 budget; capawesome is SIG (strong ecosystem, active maintenance, paid license + license-file management, vendor lock to Insiders registry → extra CI credential handling against C8). Both 🔎 only; neither verified by execution. **Recommendation-order: aparajita first, capawesome only if aparajita fails §3 acceptance.**

### 1.4 Connectivity — `@capacitor/network` (official, ADR-9)

- 🔎 Latest release: **8.0.1**, published **2026-02-12** (npm registry API: https://registry.npmjs.org/@capacitor/network — accessed 2026-10-21); peerDependency `@capacitor/core: ">=8.0.0"` (same source). - 🔎 Latest stable at access date: **2.118.0**, published **2026-10-15** (npm registry API: https://registry.npmjs.org/@supabase/supabase-js — accessed 2026-10-21). A `3.0.0-next.x` pre-release line exists — do NOT vendor a next-tag.

## 2. Verification protocol for LATER execution — ▶ **NOT RUN as of 2026-10-21**

Hard precondition **F-1** (AUDIT defect #1 + arch Phase 0): remove `android.aapt2FromMavenOverride` (Termux path) from the **tracked** `android/gradle.properties` before ANY plugin build on CI — otherwise `./gradlew assembleDebug` fails on clean checkout and no plugin can be verified. DEFAULT (⚠ not passing this gate = stop).

Per candidate (one at a time; do not stack unverifiables):

1. `npm install <pkg>@<recorded-version>` (exact pin, no `^` in the verify commit).
2. `npx cap sync android`
3. `./gradlew assembleDebug` — must succeed on **both paths**: Termux local AND GHA clean-checkout runner.
4. Device/AVD smoke via app instrumentation (small throwaway harness, deleted after capture):
   - sqlite: open DB → run 3 migrated statements (`PRAGMA user_version`, create table, insert, read back, force-kill mid-loop retry) — kill-safety check per ADR-1.
   - secure-storage: `set` token → background/kill app → `get` returns same value; confirm NOT present in the export blob.
   - network: wire `networkStatusChange` listener → toggle airplane mode → event observed + engine kick logged.
5. Record: version, install log tail, gradle outcome, smoke transcript, into this file's results section (or a new `docs/plugin-verification-results.md`).

**Dual path note (Termux + GHA):** Termux path runs the same commands locally; GHA runs them without the aapt2 override. Both must be green before any plugin is "verified".

**Acceptance criteria per plugin:** version matches a recorded pin; compile green both paths; smoke behavior matches ADR expectation; no new required Android permission beyond INTERNET (declared: AUDIT manifest check); bundle-size delta noted.

**Rollback per plugin:** revert the single plugin commit (`git revert`); `npx cap sync android` regenerates `capacitor.plugins.json`; SQLite candidate additionally: IndexedDB A/B fallback (ADR-1 pinned fallback) becomes the standing local store if the plugin is rejected — that fallback decision routes back to PL (§15 Q8).

**Failure of sqlite candidate → IndexedDB A/B fallback (ADR-1):** per-row IndexedDB stores + explicit transaction-shim for outbox commits, accepting its weaker guarantees; falls under ADR-1's "pinned fallback" clause. Not pre-built; decided only on failure.
